# ChatNotice 手机/电脑跨网络互联设计

- 日期：2026-11-22
- 状态：待实现
- 范围：桌面端公网隧道、局域网/公网双模式配对、手机扫码连接

## 1. 目标

- 保留现有局域网直连，不改变其地址、令牌和轮询行为。
- 新增可选的 Cloudflare 快速隧道，让手机在任意网络访问电脑端。
- 用户在电脑端和手机端都能明确选择“局域网”或“公网”连接。
- 手机端支持扫码自动填入地址和令牌并测试连接。

## 2. 非目标

- 不注册 Cloudflare 账号，不使用命名隧道或固定域名。
- 不实现 VPN、Tailscale、WebRTC 或自建中转。
- 不把桌面 UI 暴露到公网；公网只开放 `/api`。
- 不改变手机端待办数据流和现有令牌鉴权。
- 不保证电脑重启后公网地址不变。

## 3. 用户选择

| 项目 | 选择 |
| --- | --- |
| 公网方案 | Cloudflare 临时隧道（trycloudflare.com） |
| 账号 | 不需要 |
| 连接模式 | 局域网与公网并存，用户自行选择 |
| 公网默认状态 | 关闭，需显式开启 |
| 手机配对 | 扫码为主，手动输入保留 |
| 二维码形式 | 同时携带局域网与公网地址，手机端选择 |

## 4. 架构

| 文件 | 职责 |
| --- | --- |
| `desktop/tunnel.py` | 定位/下载 cloudflared、启动停止、解析公网地址、失败重启、状态 |
| `desktop/server.py` | 配对接口返回双模式地址与二维码、隧道开关、公网限流 |
| `desktop/ui/` | 配对弹窗增加“局域网/公网”切换、隧道状态和开关 |
| `desktop_app.py` | 启动时按持久化设置决定是否拉起隧道；退出时关闭 |
| `mobile/www/` | 配对页模式选择、扫码按钮、二维码解析、自动连接 |
| `mobile/android/` | Capacitor Camera 依赖、相机权限、重新打包 APK |

新增本地文件：

- `state/remote-access.json`：`{"enabled": false}`，记录是否允许公网隧道。
- `state/tools/cloudflared.exe`：首次开启公网时下载的二进制（加入 .gitignore 已覆盖 state）。

## 5. 连接模式

### 5.1 局域网

- 沿用当前行为：显示所有局域网 IPv4 地址，令牌不变，二维码 payload 与现有版本兼容。
- 不启动 cloudflared。
- 手机端优先使用上次成功的局域网地址。

### 5.2 公网

- 用户在电脑端配对弹窗打开“公网访问”开关后：
  1. 检查 `state/tools/cloudflared.exe`，缺失时从 Cloudflare 官方 GitHub 下载固定版本 `2026.11.1`，校验 SHA256 后再执行；
  2. 启动 `cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate`；
  3. 从 stderr 解析 `https://<随机>.trycloudflare.com`；
  4. 状态变为“已就绪”，配对二维码和地址更新为该 HTTPS 地址。
- 关闭开关或退出程序时终止 cloudflared。
- 隧道异常退出时自动重试（5 秒、15 秒、60 秒退避），新地址自动更新到界面。
- 下载失败、网络阻断、隧道连接失败时显示错误；局域网模式不受影响。

## 6. 配对二维码

二维码内容升级为 schema v2：

```json
{
  "v": 2,
  "token": "...",
  "lan": ["http://192.168.1.10:8760"],
  "remote": "https://xxx.trycloudflare.com",
  "preferred": "lan"
}
```

- `remote` 未就绪时为 null。
- `preferred` 为用户在电脑端当前选中的模式。
- 手机端兼容 v1（仅 `url` + `token`）。

## 7. 桌面端界面

配对弹窗：

- 顶部“局域网 / 公网”分段切换。
- 局域网：现有二维码、地址列表、复制按钮。
- 公网：开关、状态（未开启/下载中/连接中/已就绪/失败）、二维码、地址、复制按钮。
- 切换模式只改变展示和二维码，不自动断开另一条通道；关闭公网开关才停止隧道。
- 公网开关状态持久化到 `state/remote-access.json`，重启后按该设置自动启动隧道。
- 首次开启公网显示提示：地址会暴露到公网，待办内容经 Cloudflare 传输。

## 8. 手机端界面

- 配对页增加模式选择：“局域网（同一 Wi-Fi）/ 公网（任意网络）”。
- 增加“扫码连接”按钮：
  1. 请求相机权限，打开拍照；
  2. 本地 jsQR 解码；
  3. 读取 v2 payload，按当前选择的模式取地址：局域网取 `lan`，公网取 `remote`；
  4. 若目标模式地址不存在，提示不可用；若扫码内容同时包含两种地址，允许临时切换；
  5. 用令牌请求 `/api/status`，成功后保存并进入待办页。
- 手动输入地址和令牌的方式保留。
- 连接失败时显示具体原因，不清除已有配置。

## 9. 公网访问控制

- 公网请求必须携带 `X-Api-Token`；现有 48 位随机令牌继续使用。
- `_is_trusted_local` 已经会识别 `CF-Connecting-IP` / `X-Forwarded-For`，Cloudflare 请求不会被当作本机。
- 非本机 `/api` 请求限流：
  - 每个来源 IP 普通请求 120 次/分钟；
  - 鉴权失败 10 次/分钟；
  - 超出返回 429，`Retry-After` 30 秒。
- 静态页面、配对接口、自动读取设置接口对非本机保持拒绝或 404。
- CORS 维持现状，不放宽额外来源。
- 公网模式下不做附件直接下载；手机端仍只同步待办。

## 10. 失败处理

| 情况 | 行为 |
| --- | --- |
| cloudflared 下载失败 | 公网状态显示失败，局域网可用；提供重试 |
| 隧道启动失败/被网络阻断 | 状态显示失败，自动退避重试；不影响局域网 |
| 隧道进程退出 | 自动重启，新地址刷新二维码；手机需重新扫码 |
| 手机公网地址失效 | 连接测试失败并提示；可切回局域网或重新扫码 |
| 令牌错误 | 保留输入，提示 401；失败次数受限流 |
| 电脑休眠/关机 | 公网不可用；唤醒或重启后重新生成地址 |
| 用户关闭公网开关 | 立即停止隧道，公网地址失效，局域网继续可用 |

## 11. 测试

- 桌面端：
  - 模拟 cloudflared 输出，解析地址、重启退避和状态切换。
  - 二维码 payload v1/v2 兼容；局域网地址不因公网开关改变。
  - 公网 URL 无令牌 401、正确令牌成功、超频 429、静态路径 404。
  - 关闭开关后隧道进程终止、地址不可访问。
- 手机端：
  - v1/v2 二维码解析；模式缺失和地址缺失的错误提示。
  - 局域网连接、公网连接、连接失败回退手动输入。
  - 重新打包 APK，安装后验证相机权限和扫码。
- 手动验收：
  1. 仅局域网连接，功能与现在一致；
  2. 开启公网，手机切 4G/其他 Wi-Fi 扫码连接成功；
  3. 关闭公网后手机连接失败但局域网仍可用；
  4. 重启电脑后旧二维码失效，重新扫码可连。

## 12. 风险与取舍

- 临时隧道地址每次启动都会变化，这是免账号方案的代价；固定地址需后续接入 Cloudflare 命名隧道和域名。
- 公网可达意味着攻击面增加；依靠强令牌、限流和仅暴露 `/api` 降低风险。
- 待办内容会经过 Cloudflare，TLS 在 Cloudflare 终止；不适用于对第三方可见性极度敏感的数据。
- 首次下载 cloudflared 约 35MB，受网络影响；失败不影响局域网。
- 需要重新安装一次手机 APK。

## 13. 未决问题

- cloudflared 下载源在用户网络下的可用性，需要在实现时做一次真实连通性验证；若不可用，保留局域网并报告错误。
